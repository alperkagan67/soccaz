**Prävention (VORSCHLÄGE, höchstens drei):**
1. **Vor dem Push laufen alle Tests des betroffenen Bereichs, nicht nur die „betroffenen“ Dateien.** Für einen Turnier-PR: `tests/integration/tournament-*`, alle Struktur- und Listen-Tests (Dateilisten, Grep-Tests) und `npm test`; die Liste steht im PR-Text. Ziel: AGENTS-SETUP.md (Rolle Writer) und optional CI-Matrix (VORSCHLAG-CI-LEDGER-MATRIX).
2. **Befehle im Worktree nur als `cd <absoluter Worktree-Pfad> && …`, nie mit `;` danach; Git-Befehle, die den Branch wechseln, sind im Hauptrepo gesperrt.** Ein Hook-Guard-Zusatz (`.claude/hooks/guard.mjs`: `git checkout`, `git switch`, `git reset` mit dem Hauptrepo als Arbeitsverzeichnis blockieren) macht aus der Regel eine Sperre. Ziel: Hook (Änderung unter `.claude/`, Nutzer mergt).
3. **Nebenwirkungen in einer Webhook-Transaktion (Mitteilung, Alarm, Audit-Zusatz) laufen in einem Savepoint oder nach dem COMMIT, und parallele Zustellungen derselben Zahlung serialisiert eine Advisory-Sperre.** Jeder neue Geldpfad bekommt zusätzlich einen Test „Summe 0 je Betreff“ (je `tournament_id` oder `match_id`), weil der globale Test Zuordnungsfehler verdeckt. Ziel: Test (Muster `tournament-unmatched-error.test.ts`) und CLAUDE.md-Abschnitt „Stolperfallen“.
