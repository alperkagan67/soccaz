**Prävention (VORSCHLÄGE, höchstens drei):**
1. **Vor dem Push einer Oberflächen-, Text- oder Testid-Änderung: `git grep` über das ganze `tests/` (E2E, Integration, Unit) nach jedem geänderten Wort, Knopf, Label und jeder Testid; die Trefferliste steht im PR-Text.** Neue oder geänderte Specs werden zusätzlich in `tests/e2e-shards.json` geprüft (`node scripts/e2e-shards.mjs check`). Anlass: M6a mit drei CI-Runden. Ziel: AGENTS-SETUP.md (Rolle Writer), PR-Vorlage (Zeile „Treffer-Suche in tests/“).
2. **Sperrreihenfolge ändern heißt: Matrix aller Pfade, die dieselben Zeilenarten sperren (wer hält was, wer wartet worauf), im PR-Text und ein Test pro Paarung mit roher zweiter Verbindung; wer eine übergeordnete Sperre hält, wartet nie auf eine untergeordnete (`NOWAIT`).** Anlass: PR C, Zyklus durch die Reparatur. Ziel: `docs/BETRIEB.md` (steht dort seit PR C), Review-Checkliste.
3. **Texte mit Rechts- oder Zahlungsbezug (AGB, Hilfe, Fehlermeldungen, i18n) bleiben neutral, bis der Entscheid dazu im selben PR steht; Quelltest auf verbotene Formulierungen und ein Eintrag in `GO-LIVE-AUDIT` (Anwalt).** Anlass: M6a „ausgezahlt“. Ziel: Test (Muster `m6a-kein-guthaben.test.ts`), CLAUDE.md (Abschnitt Stolperfallen), optional.
